# 技术设计规范

> 实现时必须遵守本文档。若因实际情况需要偏离，先在此更新并说明理由。

## 一、技术选型

| 部分 | 选择 | 说明 |
|---|---|---|
| 运行时 | Python 3.12 | 本机已确认 3.12.10 |
| GUI | PySide6 (Qt6) | QSS 实现淡蓝+深色主题，自带系统托盘 |
| 上传库 | bilibili-api-python (Nemo2011) | 支持扫码/Cookie 登录、多分P上传、定时发布 |
| 音视频处理 | ffmpeg（随包捆绑静态版） | 拆分 / 可选合并 |
| 定时 | APScheduler | 进程内定时 + 托盘常驻 |
| 打包 | PyInstaller | 产出双击即用的 .exe |

> 注意：PyPI 包名是 `bilibili-api-python`（不是 `bilibili-api`），import 名为 `bilibili_api`。已装版本 17.4.2。

## 三、数据存储

- 目录：`%APPDATA%/BiliAutoUpload/`（即 `C:\Users\<用户名>\AppData\Roaming\BiliAutoUpload\`），不占用程序目录；旧版 `程序目录/data/` 会在首次启动时自动迁移过来。
- 配置：`config.json`（UTF-8），加载时与默认值合并，保证新增字段有默认值。
- 历史：SQLite 数据库 `history.db`，表 `uploads`：
  `id, path, size, mtime, title, bvid, part_count, status, created_at`。
  去重依据：`path + size + mtime`。
- 凭据：`credential.json`（字段 base64 混淆），cookie 过期后自动用 refresh_token 续期（实现自动登录）。

## 四、配置项规范（config.json 字段）

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| folders | list[dict] | [] | 文件夹列表，每项 `{"path":..., 以及可覆盖的投稿设置}`；旧 `watch_folders` 自动迁移 |
| video_extensions | list[str] | .mp4/.flv/.mkv/.mov/.avi/.wmv/.ts/.m4v | 视频扩展名 |
| schedule_times | list[str] | ["08:00"] | 每天时间点 "HH:MM" |
| title_template | str | "{folder} {date} 第{index}期" | 主标题 |
| part_title_template | str | "P{part_index}" | 分P标题 |
| desc_template | str | "" | 简介 |
| tags | list[str] | [] | 标签 |
| cover_path | str | "" | 封面路径，空=不设 |
| tid | int | 160 | 分区ID |
| copyright | int | 1 | 1原创 / 2转载 |
| source | str | "" | 转载来源 |
| multi_file_strategy | str | "multipart" | multipart/merge/separate |
| split_threshold_gb | float | 3.5 | 拆分阈值 |
| publish_mode | str | "timed" | public=直接发布 / timed=延迟发布 / schedule=定时到指定时刻 |
| publish_delay_hours | float | 2.0 | 延迟发布模式下，上传后延迟公开的小时数 |
| publish_schedule_time | str | "20:00" | 定时发布模式下，发布的具体时刻 "HH:MM" |
| cleanup_mode | str | "archive" | archive/delete/none |
| archive_folder | str | "" | 归档目录，空=监控目录下 auto_archived |
| auto_start | bool | false | 开机自启 |
| minimize_to_tray | bool | true | 关闭时最小化到托盘 |
| upload_workers | int | 3 | 上传并发数 |
| max_retry | int | 3 | 重试次数 |

## 五、命名模板变量

`{date}` 日期(YYYY-MM-DD)、`{time}` 时间(HHMM)、`{index}` 当天序号(从1)、`{part_index}` 分P序号、`{original_name}` 原文件名(去扩展名)、`{folder}` 所在文件夹名、`{count}` 当天总数。

## 六、代码规范

- 语言：中文 docstring / 注释 / 日志 / 界面文案。
- 每个模块：`logging.getLogger(__name__)` 记录关键流程；异常捕获后写日志，不让程序崩溃。
- 类型注解 + 简洁 docstring。
- 上传、拆分、扫描等耗时操作放在 `QThread` 后台执行，UI 主线程只负责展示与进度。

## 七、线程模型

- Qt 主线程：UI 事件循环。
- 后台 `QThread`/`QObject` worker：扫描、ffmpeg 拆分、上传。
- worker 通过 Qt 信号把进度/结果发回主线程更新 UI，禁止在 worker 里直接操作控件。

## 八、安全与容错

- 凭据（Cookie）落盘前做基础混淆，启动与每次运行前校验登录态，过期提示重新登录。
- 发布默认「延迟发布」（公开前可人工确认）；删除/发布类操作在 UI 中给明确提示。
- B 站内部接口可能变动：上传逻辑集中在 `uploader.py`，库升级只改这一处。

## 九、发布方式与 bilibili-api 能力对照

| 需求 | 实现方式 | 状态 |
|---|---|---|
| 直接发布 | `VideoMeta` 不带 `delay_time`，立即公开 | ✅ 原生 |
| 延迟发布（N 小时） | `delay_time = 现在 + N 小时`（秒） | ✅ 原生 |
| 定时到指定时刻 | `delay_time = 下一个 HH:MM 的时间戳`（秒） | ✅ 原生 |
| 仅自己可见 / 存草稿 | 提交接口 `/x/vu/web/add/v3` 无可见性字段，库不支持 | ❌ 暂不支持 |

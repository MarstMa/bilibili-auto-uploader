# 实验版本流程

本仓库用分支区分「稳定版」与「实验版」：

| 分支 | 用途 |
|---|---|
| `main` | 稳定版，发正式 release（`vX.Y.Z`） |
| `experimental` | 实验版，发预发布（prerelease，tag 带 `-dev` 后缀） |

## 为什么实验版要用「预发布」

自动更新走 GitHub 的 `releases/latest` 接口，该接口**只返回最新正式版，会忽略所有预发布**。因此实验版标记为 prerelease 后，**不会触发正式用户的自动更新**。

## 发实验版步骤

1. 切到 experimental 分支：
   ```bash
   git checkout experimental
   ```
2. （开发 / 改代码后）打包：
   ```bash
   python build/build.py
   ```
3. 发布为预发布：
   ```bash
   gh release create v0.3.0-dev dist/BiliAutoUpload.exe --prerelease --title "v0.3.0-dev 实验版" --notes "实验内容说明"
   ```

## 实验版转稳定版

实验版测试稳定后，合并回 main 并发正式版：
```bash
git checkout main
git merge experimental
python build/build.py
gh release create v0.3.0 dist/BiliAutoUpload.exe --title "v0.3.0" --notes "更新说明"
```

> 说明：实验版与稳定版共用同一套源码，只是通过「分支 + 预发布 tag」区分，无需新建仓库。
